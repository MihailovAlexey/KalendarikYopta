# Календарь мероприятий для Telegram Mini App

## 1. Цель проекта

Сделать Telegram Mini App, в котором пользователи смогут:

- просматривать календарь мероприятий на лето;
- видеть сводную информацию по каждому мероприятию;
- открывать карточку мероприятия с деталями и ссылками;
- подписываться на мероприятие и получать напоминания перед его началом.

Отдельно нужен режим управления контентом для владельца проекта, чтобы можно было добавлять и редактировать мероприятия без возможности редактирования для обычных пользователей.

## 2. Основные роли

### Администратор

Может:

- создавать мероприятия;
- редактировать мероприятия;
- менять цветовую маркировку;
- добавлять комментарии;
- публиковать и скрывать мероприятия;
- смотреть список подписавшихся пользователей.

### Пользователь

Может:

- просматривать список и календарь мероприятий;
- открывать карточку мероприятия;
- переходить по ссылкам;
- подписываться на уведомления по конкретному мероприятию;
- отменять подписку на уведомления.

Не может:

- изменять данные мероприятий;
- добавлять свои события;
- редактировать комментарии и цвета.

## 3. Что должно храниться у мероприятия

Минимальный набор полей:

- `title` — название мероприятия;
- `start_date` — дата начала;
- `end_date` — дата окончания, если мероприятие длится несколько дней;
- `place` — место проведения;
- `city` — город, если нужен отдельно от площадки;
- `link` — ссылка на регистрацию, пост или сайт;
- `comment` — комментарий администратора;
- `color` — цветовая метка для отображения в календаре;
- `status` — например: `draft`, `published`, `cancelled`;
- `registration_deadline` — если есть дедлайн регистрации;
- `tags` — опционально, например `drift`, `festival`, `track day`;
- `created_at`, `updated_at`.

## 4. Пользовательские сценарии

### Просмотр

Пользователь открывает мини-приложение и видит:

- календарный вид по месяцам;
- список ближайших мероприятий;
- цветовые метки;
- краткую карточку: дата, название, место, статус или комментарий.

### Детали мероприятия

При открытии карточки пользователь видит:

- обложку;
- полное название;
- даты;
- место;
- ссылку;
- комментарий;
- кнопку подписки на уведомление.

### Подписка на уведомление

Пользователь нажимает кнопку подписки, а система:

- сохраняет его Telegram ID;
- привязывает пользователя к мероприятию;
- отправляет уведомление за заданное время до начала.

## 5. Ключевое ограничение Telegram

Одного Mini App недостаточно для уведомлений.

Чтобы отправлять напоминания пользователям, понадобится:

- Telegram-бот;
- backend-сервис;
- база данных;
- планировщик задач, который будет запускать отправку уведомлений по времени.

Практически это означает, что правильная схема для MVP:

- Mini App для интерфейса;
- бот для авторизации входа и уведомлений;
- backend API;
- база данных.

## 6. Варианты управления мероприятиями

### Вариант A. Управление через Google Sheets или Airtable

Плюсы:

- самый быстрый старт;
- удобно редактировать руками;
- не нужно сразу делать полноценную админку;
- таблица интуитивна для ввода событий.

Минусы:

- придется делать синхронизацию таблицы с приложением;
- сложнее контролировать структуру данных;
- уведомления и подписки все равно надо хранить отдельно в базе.

### Вариант B. Отдельная админка

Плюсы:

- полный контроль над полями;
- можно красиво сделать цвета, фильтры, статусы;
- проще держать все данные в одной системе.

Минусы:

- дольше делать;
- выше стоимость MVP по времени.

### Вариант C. Гибридный подход

Схема:

- события хранятся в базе;
- на старте управление идет через готовый интерфейс базы или простой внутренний экран для администратора;
- позже добавляется полноценная админка.

Это выглядит самым рациональным вариантом для MVP.

## 7. Рекомендация для MVP

Рекомендуемая реализация:

1. Telegram-бот как точка входа.
2. Telegram Mini App для просмотра календаря.
3. Backend на `Node.js`/`TypeScript`.
4. База данных `PostgreSQL`.
5. `Supabase` как самый простой способ быстро получить:
   - PostgreSQL;
   - авторизацию и хранение данных;
   - удобную таблицу для ручного редактирования на старте;
   - серверные функции при необходимости.
6. Уведомления через бота и cron-задачи.

Почему это хороший старт:

- не нужно сразу писать сложную админку;
- события можно редактировать через интерфейс Supabase Table Editor;
- обычные пользователи будут видеть только frontend;
- позже можно добавить отдельную красивую админ-панель без смены базы.

## 8. Предлагаемый MVP-функционал

### Обязательно

- список мероприятий;
- календарный вид по месяцам;
- карточка мероприятия;
- ссылка на внешний ресурс;
- комментарий;
- цветовая метка;
- подписка на напоминание;
- read-only доступ для обычных пользователей;
- управление событиями только для администратора.

### Можно отложить на второй этап

- фильтры по городам и типам событий;
- избранное;
- несколько типов напоминаний;
- импорт из таблицы;
- статистика просмотров и подписок;
- несколько администраторов с разными правами.

## 10. Решение по управлению данными

Если нужен быстрый и практичный старт, лучше идти так:

1. На первом этапе хранить мероприятия в `Supabase`.
2. Редактировать их через встроенный Table Editor или очень простой внутренний экран только для администратора.
3. Для пользователей сделать только просмотр и подписку.
4. Уведомления отправлять через Telegram-бота.

Это даст работающий MVP без лишней сложности.

## 11. Открытые вопросы

- Нужен ли только один администратор или несколько?
- Должны ли пользователи видеть мероприятия только списком, или нужен именно календарь-сетка по дням?
- Нужно ли деление по категориям: дрифт, фестиваль, трек, сходка?
- Нужна ли модерация перед публикацией изменений?
- За сколько времени до события отправлять уведомления: за день, за 3 дня, за час?
- Нужно ли хранить несколько ссылок у одного мероприятия?
- Нужна ли загрузка афиши или обложки для каждого мероприятия?
